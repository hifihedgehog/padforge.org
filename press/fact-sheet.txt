PadForge
Product information | November 21, 2026

PadForge is a free controller remapper for Windows. It maps gamepads, wheels, flight sticks, keyboards and mice onto as many as 16 virtual controllers, knows 2,687 devices by their USB identity and lights 1,572 RGB devices by itself. Players can tune stick response and gyro aiming, build macros and save profiles for individual games. PadForge also imports supported Steam community layouts, reWASD configs and DS4Windows profiles, and connects browser-based controllers. Its source code is available under CC BY-NC-SA 4.0.

New in 6.0.0
PadForge 6: The interface is rebuilt around what most people do first, and no setting is removed. Home replaces the Dashboard: one switch starts the engine, and each virtual controller has a card with a picture of its controller that lights as you press. On a first run, one click makes the first controller for the connected device, mapped 1:1. The services that stood on the Dashboard are tiles on a new Extras page, and each opens a page of its own. A controller's tabs become six sections: Mappings, Sticks & Triggers, Rumble & Haptics, Motion & Touch, Lights & Sound, and Macros & Menus. Ctrl+K finds pages, controllers, devices, profiles, settings and actions.
Wheel centering from a car's steering: A force feedback wheel can center the way a car's steering does. The new Centering card keeps the plain spring as Spring mode and adds Vehicle mode, which puts on the rim the torque a car's steering gives at its speed and grip. It offers a Sedan, a Compact, a Van, a Race Car and the Stanford X1, and reads the speed from your game's telemetry. Release Test measures the wheel with your hands off it and sets the damping that brings it back without swinging past center.
Crosshair and Magnifier: Two new extras. Crosshair shows up to ten crosshairs over your game, each a cross, a circle, a dot or a picture of your own. Magnifier is a lens like a sniper scope, the whole display zoomed in, or a spotlight that darkens the rest, at 1.25 to 16 times. Macros show and hide either one, and one shows the magnifier only while a button is held.
Flydigi Apex 4, Apex 5 and Apex 6 Pro: These pads get what a DualSense or an Xbox pad gets on a virtual controller: adaptive trigger effects, impulse triggers and their own lights on the Lighting card. Controller Screen, on the Devices page, sends a picture or a GIF to the pad's screen by cable. The Apex 4, in DInput mode, and the Apex 5 have triggers that resist. The Apex 6 Pro's trigger coils vibrate, and its grip coils play the DualSense haptic track.
SInput pads: SInput is Hand Held Legend's HID gamepad protocol. A pad that speaks it arrives with its buttons, sticks, triggers, motion, touchpads, battery and rumble, and plays PadForge's sounds on its haptics. An Extended virtual controller can be an SInput Gamepad too.
Polling up to 10,000 Hz: The polling rate is set in hertz, from 60 to 10,000, in Settings and in each profile. The default stays 1,000 Hz. It was a whole number of milliseconds, and a saved interval becomes its rate as it loads. On a PC whose timer wakes the engine 2,000 times a second, a higher rate runs several passes at each wake.
HIDMaestro 2.3.0: 344 device profiles, of which PadForge offers 246. Six are new: the Xbox One S Controller (Model 1708): Full, the USB forms of the Nintendo Switch Online Genesis, N64 and SNES pads, and the Joy-Con Charging Grip with the left or the right Joy-Con. On Windows on ARM every virtual controller now runs as a USB device that Windows' own drivers bind.
More RGB devices: PadForge lights 1,572 RGB devices by itself, among them the ROG Falchion Ace 75 HE key by key, Cooler Master's MK721 and CK721 LINE, the Roccat Kone XTD and the light bars of the Corsair K70 PRO MINI WIRELESS.

Setup
PadForge runs as administrator. Its runtime is included in the executable.
HIDMaestro provides virtual controller output and is installed when needed.
Virtual controllers that are USB devices install usbip-win2's host controller the first time one is created: every virtual controller on Windows on ARM, and on x64 the composite controllers, the Steam Controller (2026), the Xbox One S: Full profile and the Joy-Con Charging Grip forms.
PadForge 4.5.3 and later update themselves from the Updates card in Settings.
Installation and removal: https://padforge.org/docs/start/installation/

Untested hardware and other limits
No wheel has run wheel centering. Every stability and Release Test result
comes from a simulated wheel. A wheel whose maker publishes no torque
figure, Thrustmaster's among them, starts from a high figure, so its forces
are weak until its own Wheel Torque is entered. Over Remote Link, centering
reaches a Logitech, Fanatec or Thrustmaster wheel only. A game with no
telemetry uses the Fixed speed.
No Logitech wheel has run the switch to native mode, and no Logitech RS50
has run as a wheel.
No Flydigi pad has run against PadForge. The screen takes a picture by
cable only. An Apex 4 send needs every other Xbox 360 pad unplugged. The
plain Apex 6 is refused.
No SInput pad has run against PadForge, and no game has run on the SInput
Gamepad.
No PadForge build has driven any of the six new HIDMaestro profiles.
An ARM64 build of this release has run on one Windows 11 ARM64 PC, with a
virtual Xbox controller and a hidden DualSense, before the last HIDMaestro
update. The other virtual controller types have not run on ARM64 hardware.
A game in exclusive full screen hides the crosshairs, the lens and the
spotlight. Windows' full-screen magnifier serves one program at a time.
Above 1,000 Hz, what a game reads from a virtual controller whose frames
carry a clock has not been measured.
The interface was checked in page renders, UI Automation and the NVDA
screen reader. No controller was put through every page by hand.
None of this release's lighting changes has run on a device. Most of the
1,572 RGB devices PadForge lights have not run against PadForge. Their
frames follow the references' own code, checked by running those
references against PadForge's tables.
A Joy-Con 2 clone such as the Mobapad M12-S is expected to pause for a
moment about every 30 seconds. Before, it was lost for good. No clone has
run this build.
The direct rumble paths for mice and keyboards follow the public
implementations that drive each device, and tests check every frame
against them. They have not run on the devices themselves.
Twitch Chat has not run against a live channel.
No Corsair LT100 or LS100 has run against PadForge.
No wired second-model DualShock 4 or Sony USB wireless adapter has run
the 5.2.0 audio routing or the 5.3.0 speaker route.
No Mayflash DolphinBar has run the 5.3.0 fix that keeps its empty slots
from becoming Wii Remotes.
Use Only in PadForge has switched one keyboard and one mouse and given them
back, and a precision touchpad taken this way clicked and scrolled. No key
or button read through it has been confirmed yet.
A reWASD or DS4Windows import marks a binding Clean when the translation
keeps its behavior. Clean is not a play test.
No native speaker has reviewed the translations. A partial translation
shows English wherever it has no string.
No NYXI Hyperion 3 has run against PadForge.
No Novint Falcon and none of the supported keyboard screens has run
against PadForge. No Fanatec base has run the report 0x01 fix.
DualSense audio over Bluetooth uses a virtual USB DualSense for compatible
games. The game supplies its native speaker audio and haptic effects.
Steam imports include a translation report. Some bindings are approximated
or skipped. Game-specific Steam Input API actions do not translate.
